# 未知环境导航接口契约 v1

更新时间：2026-11-13。本文固定接口；当前尚未实现自主探索和中间目标管理。

## 坐标、单位与时间

- 地形地图使用map坐标，米，Z向上；当前仿真map=world。规划输入仍为二维位置与最终航向。
- 原始点云使用lidar_link；/lidar/points_map是采集时刻三维位姿配准后的同一批观测，不是完整场景点云。
- 测量时间统一使用消息header.stamp和/clock仿真时间；墙钟单调时间只用于检测进程/反馈失联，二者不得直接相减。
- /lidar/ground_truth_odometry提供map→lidar_link的完整三维真值位姿。Nav2的/odom、base_link由已有状态桥提供。后续真实定位必须替换位姿来源并保持TF一致。

## 上下游接口

| 接口 | 类型 | 内容与使用方 |
|---|---|---|
| /lidar/points | sensor_msgs/PointCloud2 | lidar_link坐标XYZI；当前intensity=0占位 |
| /lidar/points_map | sensor_msgs/PointCloud2 | map坐标观测，输入CMU |
| /lidar/ground_truth_odometry | nav_msgs/Odometry | 雷达中心完整位姿，输入CMU |
| /terrain_map | sensor_msgs/PointCloud2 | CMU输出；intensity是相对地面高度差（米），不是0—100代价 |
| /traversability_map | nav_msgs/OccupancyGrid | 全局图，供全局规划与目标准入使用 |
| /traversability_map_local | nav_msgs/OccupancyGrid | 近期观测图，供局部控制使用 |
| /navigation/mapping_status | std_msgs/String，JSON v1 | 地图就绪、原因、会话、版本、全局/局部计数与存档错误 |
| /navigation/navigate_to_goal | nav2_msgs/action/NavigateToPose | 激光模式用户最终目标入口，允许未知及当前边界外终点进入有限探索，管理中间观察目标 |
| /navigate_to_pose | nav2_msgs/action/NavigateToPose | 原生Nav2已知区子目标；offline模式仍直接使用 |
| /navigation/task_records | std_msgs/String，JSON v1 | 每个客户端的任务编号、目标、Action UUID、历史与停车结论 |
| /navigation/task_status | std_msgs/String，兼容原字段 | 原安全监视状态及控制许可，附客户端记录 |
| /navigation/mission_status | std_msgs/String，JSON v1 | 上层阶段与当前请求、活动任务、地图状态；用于面板与后续调度 |
| /navigation/cancel | std_srvs/srv/Trigger | 请求取消；请求提交不等于取消已完成 |
| /mapping/save | std_srvs/srv/Trigger | 原子保存当前全局/局部地图，响应返回目录或错误 |
| /mapping/reset | std_srvs/srv/Trigger | 两张图重置为未知、地图ready撤销，等待新观测；旧活动任务由监视器停止 |

全局和局部地图初始32×32米、0.2米/格，初始原点(-16,-16)，按观测自动扩展，当前最大256×256米。以每条消息的width/height/origin为准，不得硬编码160格。cost[row_y,col_x]，ROS数据按行展开；-1未知、0—99通行代价、100禁行。图中保存基础通行代价，Nav2另做足迹和安全膨胀。当前已知安全的占据足迹清理只发生在Nav2层，不改变原始感知图。

第3步已启用按观测扩图，新增边框未知、历史世界坐标不变；超出当前已分配范围的目标不能直接交给原生Nav2；在线入口已允许其进入有限探索，随着真实观测扩图后重新检查终点。第4步已将LIO内部图/lio前缀、lio_map坐标经一致快照核对转发至本表标准话题，主导航入口默认LIO。/navigation/mapping_status.source为cmu_lio；显式truth模式保留cmu_lidar。见LIO接管Nav2阶段4.md。

## 两张地图的更新规则

1. 全局图在同一定位会话内长期保留已探索区域，不再因30秒未观测而遗忘；新观测可替换同格旧代价。
2. 局部图保留最近3个仿真秒的地形输出，过期恢复未知，不是自由。没有正面观测证据，不能仅凭“障碍没再出现”清空格子。
3. 新一帧同格多点取最大代价；后续明确观测到该格地面时，可以将旧障碍代价替换为地面代价。
4. CMU自身缓存保留2秒，noDecayDis=0，不再永久保留近处旧点；因此移走障碍的更新有观测与缓存延迟。被遮挡或未重观测的全局旧障碍保持，属于保守记忆。
5. 会话变化或仿真时间倒退时清空坐标相关历史。更换定位会话应整套重启CMU，避免上游缓存混入不同坐标系。
6. 地图有历史数据不等于允许运动。雷达、地形、定位反馈失效时仍撤销许可，不能靠旧全局图继续走。

## 上层阶段

mission_status固定字段：schema_version、phase、reason、reason_code、task_id、goal_id、current_request、control_permitted、pose、map_revision、mapping、parking_status、exploration_enabled。

| phase | 含义 |
|---|---|
| waiting_ready | 等待系统/定位等启动条件 |
| waiting_observation | 等待有效地图或目标区域观测 |
| ready | 系统可接收目标 |
| navigating | Nav2正在执行目标 |
| canceling | 等待取消完成 |
| arrived | Nav2返回成功，停车结论单独看parking_status |
| canceled | Action已取消 |
| blocked | 目标被拒绝或执行失败，尚无自动换路调度 |
| fault | 状态、地图或定位故障；旧故障任务不会自动续跑 |
| exploring | 正在前往已知安全观察点以扩展地图；激光模式exploration_enabled=true |

新请求被拒绝不会覆盖仍在执行的旧任务。current_request保存最新请求，task_id/goal_id用于关联实际Action；外部客户端直接发原生Action时，项目task_id可能为空。

系统reason_code包含robot_state_timeout、mapping_not_ready、wrong_map_source、map_invalid、tf_missing、tf_stale、session_changed；任务准入码沿用unknown、map_not_ready、outside、occupied、stopping_cost等；在线范围外探索使用target_outside_current_map，状态含initial_target_outside及target_outside_current_map。中文reason用于显示，程序不要解析中文字符串做判断。

## 地图存档

有一键启动会话时，默认保存到该次forest_navigation/results/startup/<会话>/maps/<定位会话哈希>/；独立运行默认forest_lidar_perception/results/live/maps/。可用FOREST_NAV_MAP_ARCHIVE指定存档根目录。

每5个墙钟秒在有变化时自动保存，并可调用/mapping/save立即保存。每个会话目录包含global.npz、local.npz和metadata.json；数组包含cost、observed_at、resolution、origin、frame_id、session、revision。程序退出时尝试最后保存。storage_error会报告写入失败。

新会话不自动加载旧图：当前缺少跨会话定位对齐，直接加载可能导致坐标错位。磁盘保存与同会话长期记忆已实现，跨会话重定位/加载属于后续工作。

第3—6项已实现，未知目标、探索与取消规则见[未知导航3456说明.md](未知导航3456说明.md)。

## 地图健康修复后的契约（2026-11-13，以本节为准）

- 模拟器每步原子更新雷达帧目录下lidar_progress.json，字段stamp、session、sent_monotonic。ROS雷达桥用它区分仿真步进与5Hz采样，独立心跳或时钟推进超过0.5墙钟秒未更新则无效。
- /lidar/status现在是约20Hz墙钟健康心跳，stamp/sequence仍指向最后一帧实际测量。心跳不代表新点云，重复点云不发布；CMU不会因心跳获得新观测。
- 雷达测量最大年龄为两个仿真采样周期，当前0.4仿真秒；地形为三个周期，当前0.6仿真秒。它们从lidar.json的frequency_hz启动时计算。
- 地图仍检查雷达状态心跳1墙钟秒失联；删除了要求CMU两墙钟秒内必须输出测量的规则。仿真暂停由步进/机器人状态看门狗处理，CMU挂起且仿真继续则由地形仿真年龄处理。
- 坏帧和乱序帧不能刷新有效观测时间；上一有效观测在原期限内继续有效，真正过期仍停止。单帧错误保存在diagnostics.last_rejection，不伪造成功测量。
- 消息时间戳倒退不再清图。明确重置、会话/时钟代号变化或确认/clock回退才清图，并增加reset_generation；上层管理器和安全监视均据此终止旧任务，即使地图很快恢复ready也不会静默续跑。
- 原有全局地图保留、局部3仿真秒TTL、未知不填自由、Nav2足迹/膨胀规则保持不变。此机制服务于当前仿真接口，不能直接作为真机传感器时间同步协议。

激光/IMU同源采集已接入。后续LIO使用/imu/data_raw和/lidar/points_synced，外参、时间域、会话重启与缺样规则以[激光IMU接口_v1.md](激光IMU接口_v1.md)为准；原CMU与Nav2仍使用真值接口，本阶段没有接管定位。
