# 第2步：独立激光惯性定位与点云建图

后续第4步已正式接入Nav2；森林主入口默认LIO，本文保留第2步独立估计阶段的历史说明，最新用法见[LIO接管Nav2阶段4.md](LIO接管Nav2阶段4.md)。

本阶段将原始激光和IMU接入现成FAST-LIO，在旁路估计机器人位姿、积累三维点云地图。当前Nav2仍使用原真值定位；没有将估计结果冒充已经替换了导航定位，也没有训练策略。

## 一键启动

```bash
/home/ubuntu/robot_projects/forest_nav/forest_lidar_perception/start_lio_mapping.sh
```

启动森林、G1既有策略、激光/IMU、FAST-LIO，默认不发送运动目标。先站立初始化约4秒仿真时间，随后开始输出估计位姿和地图。Ctrl+C关闭并保存本次结果。

已有仿真和传感器正在运行时，只启动估计器：

```bash
ROS_DOMAIN_ID=186 /home/ubuntu/robot_projects/forest_nav/forest_lidar_perception/start_lio.sh
```

域号须与传感器相同；独立一键入口默认191，全导航入口默认186。禁止重复启动同一套估计器。需要重新构建时运行同目录build_lio.sh。

有限检查入口：

```bash

# 一次实际运动检查：等LIO初始化后，由原导航控制G1到(6,1.5)。
```

运动检查使用原来已跑过的basic场景目标和保护逻辑，不用LIO反馈控制机器人。结果保存在results/lio_时间/；包含map.pcd、trajectories.npz、aligned_trajectory.csv、verification.json和各进程日志。

## 接口

| 方向 | 话题/服务 | 数据与用途 |
|---|---|---|
| 输入 | /lidar/points_synced | 本体坐标XYZI/ring/time；IMU已覆盖本帧 |
| 输入 | /imu/data_raw | 200Hz角速度、比力；不提供真值姿态 |
| 输入 | /clock、/sensors/sync_status | 仿真时钟、连续性/会话检查 |
| 输出 | /lio/odometry | nav_msgs/Odometry，lio_odom下的lio_imu位姿 |
| 输出 | /lio/path | nav_msgs/Path，独立估计轨迹 |
| 输出 | /lio/cloud_registered | 估计位姿配准后的当前点云 |
| 输出 | /lio/map | FAST-LIO维护的局部点云地图 |
| 输出 | /lio/status | 初始化/数据状态、点云及位姿计数 |
| 服务 | /lio/map_save | std_srvs/Trigger，保存累计点云map.pcd |

原有map→odom→base_link与真值传感器TF继续服务现有导航。新增独立lio_odom→lio_imu→lio_lidar分支，不与map连接。RViz查看这些点云时将Fixed Frame设为lio_odom。上游原始camera_init/body TF发往/lio/internal_tf，未进入公共TF树。

## 适配做了什么

选用Hesai维护的ROS2 FAST-LIO分支，提交固定在dependencies.lock.json。上游源码未修改，项目本地独立构建，不安装到系统。算法输入只有传感器数据；/lidar/ground_truth_odometry只由评估程序订阅。

上游解码器使用timestamp:float64；适配器将time:float32转换为该字段，保留XYZI/ring与原header时间。JT32配置只用于复用32线字段解码，不声称仿真了对应雷达。所有点内时间仍为0，未按方位角虚构旋转扫描。上游会有一次“扫描跨度0ms”的提示，这是当前瞬时扫描模型的已知差异。该分支读取0时间点后扫描起止相同，没有凭空增加一圈扫描时间。

原IMU以rad/s、m/s²输入，明确关闭自动单位猜测、自动时间偏移和在线外参估计。启动时从实际传感器配置计算T_imu_lidar，覆盖算法外参。初始化前2秒跳过，之后2秒积累静止IMU；一键运动检查会等初始化完成才发目标。

传感器时钟代号/会话变化或IMU缺样时整组估计器退出，要求重新启动；没有尝试在旧地图上继续拼接另一段时间。初始化前session为空的等待状态不视为会话切换。当前没有自动重定位恢复。

## 评估与边界

对比相同测量时间的完整6DoF真值与估计IMU位姿，先用安装外参把真值激光位姿转到IMU。只用首对位姿确定固定SE(3)对齐，不用整条轨迹拟合、不调整尺度。上游秒转整数纳秒存在截断，仅容许2纳秒数值差，不匹配相邻扫描、不插值或修改估计轨迹。

短程检查要求至少40对位姿、位置RMSE小于0.5m、终点误差小于0.75m、成功保存地图；运动检查额外要求原导航成功且位移大于2m。这是初步集成门槛，不是长期未知环境定位精度保证。

本阶段是局部LIO及点云建图，没有完成回环、跨会话重定位、地图自动扩展或Nav2定位接管。理想IMU尚无噪声/偏置模型，激光尚无逐束运动畸变；不能据此认定真机迁移已经完成。

实现位置：lio.launch.py负责进程和隔离；config/fast_lio.yaml负责算法参数；nav2_path_tracking/forest_nav_control/lio_adapter.py负责字段与输出；run_lio.py负责独立启动/有限验收；lio_evaluation.py负责与真值比较。
