# 激光雷达感知接入：第1、2步

此目录接入CMU Humble地形分析包和G1独立3D激光雷达。独立雷达入口不启动Nav2；另有激光在线导航入口，见文末第3—5步。默认森林导航入口现已切换激光模式，旧离线模式可显式选择。G1策略本身原有深度输入保持原样，上层点云不使用相机深度。

## 已接入内容

- third_party/cmu_autonomy：官方Humble分支，只检出terrain_analysis和terrain_analysis_ext，固定提交见dependencies.lock.json。未修改官方源码。
- build_cmu.sh：只构建这两个包，输出到本目录build/install，不写入系统。
- config/lidar.json：32线、水平360°、水平角分辨率1°、垂直[-85°,15°]、0.2—20米、5Hz。安装在现有torso绑定帧上方0.65米，跟随完整三维姿态。
- nav2_path_tracking/forest_nav_control/lidar_sensor.py：调用IsaacLab MultiMeshRayCaster与LidarPattern，射线针对实际USD林地全部几何，包括树冠、树干、地面和倒木；机器人网格用于自遮挡。它是理想几何雷达，不是RTX光学/材质强度仿真。每帧瞬时扫描，无逐束运动畸变、噪声、多回波模型；intensity填0表示尚未模拟反射强度。
- nav2_path_tracking/forest_nav_control/lidar_bridge.py：跨Kit Python3.12与ROS Python3.10交接最新一帧并发布标准ROS消息。本机交接采用原子NPZ文件，不依赖两边Python混装。后续真机用雷达ROS驱动替代这一桥接入口。

## 启动

    ./start_lidar.sh

默认打开G1与basic三维林地，保持零速度输入，持续发布雷达；Ctrl+C关闭本次进程。图形窗口展示场景，不默认绘制全部点云。启动只建立独立雷达数据链，不启动CMU地形分析或Nav2。

最小检查入口：

    ./start_lidar.sh --check --timeout 180

无界面启动，收到3帧非空雷达点云并检查坐标帧、有限数值和量程后退出。空初始化帧不计入通过条件。结果和日志保存在results/<时间>/，失败记录保留。该检查不等于地图或导航验收。

## ROS接口

| 话题/TF | 类型 | 约定 |
|---|---|---|
| /lidar/points | sensor_msgs/PointCloud2 | lidar_link坐标，XYZI，米；intensity为0占位 |
| /lidar/points_map | sensor_msgs/PointCloud2 | 相同观测点，用采集时刻三维真值位姿配准到map；不是场景完整点云 |
| /lidar/ground_truth_odometry | nav_msgs/Odometry | map→lidar_link，完整xyz和xyzw；这里是雷达中心位姿，不是机器人根坐标位姿 |
| map→lidar_link | TF | 与点云相同采集时刻 |
| /lidar/status | std_msgs/String，JSON | 帧序号、点数、就绪/过期状态 |
| /clock | rosgraph_msgs/Clock | 仅独立传感器入口发布；以后共用旧状态桥时关闭此处时钟发布 |

ROS域默认191，与现有导航模式隔离。雷达状态只用于观测，不控制机器人。完整三维机身位姿也保存在latest_frame.npz的body_pose内；上述里程计发布的是CMU裁剪所需的传感器中心位姿，不可直接当作base_link定位。

## CMU构建与下一步接口

    ./build_cmu.sh

两个官方包已编译通过，未运行完整CMU系统。仓库地形分析源码有一条上游运算符括号警告，未擅自改其源码。

提供后续第3步使用的入口，但当前独立雷达启动不会自动调用它：

    ./start_cmu.sh

该入口将官方/registered_scan映射到/lidar/points_map，/state_estimation映射到/lidar/ground_truth_odometry，输出保留/terrain_map。必须在相同ROS域中运行。这里只预留remap和高度参数，尚未完成点云→地形输出验收。CMU输出intensity包含相对地面高度等含义，不能直接当作0—100标准栅格代价。

## 本轮最小验证结果

CMU两个包构建通过。G1实际采集的一帧包含11,520束射线、9,830个有效点，回波距离约2.188—19.237米。使用该采集帧核对sensor→world转换，最大坐标误差约4.77e-7米；经真实ROS发布与接收，点数和坐标一致。结果见results/lidar_interface_verification.json。

过程记录如实保留：早期安装点处于自身遮挡区，输出为空；抬高后产生有效点云。第一次有效点云检查又遇到检查器按普通数组读取ROS结构化数组的问题，已改为官方read_points_numpy接口，并用已采集帧回放验证，没有再为此启动G1。因此，本轮通过的是实际采集帧及ROS接口核对，**不是--check连续3帧整项通过记录，也不是CMU地形分析或导航通过**。仿真检查已结束。

## 2026-11-13：第3、4、5步接入

一键启动实际激光在线地图、Nav2、G1与坐标面板：

    ./start_lidar_navigation.sh

等价入口：

    ../forest_navigation/start_forest_navigation.sh --map-mode lidar

只检查整套就绪，不发送目标并自动关闭：

    ./start_lidar_navigation.sh --headless --check-ready --startup-timeout 150

数据流：实际G1激光射线 → /lidar/points_map与采集时刻完整三维雷达位姿 → 原版CMU terrainAnalysis → /terrain_map → terrain_costmap.py → /traversability_map → 原有Nav2、速度适配和G1。

- 新模式只启动CMU地图链，不启动早期相机在线原型；即使误传publish_map:=true也不会发布离线全图。已有离线高程文件仍供原有仿真跌倒检查和路线显示贴地使用，不输入CMU或代价地图转换。
- config/terrain.yaml配置官方模块，不改其源码。CMU intensity为相对地面高度差（米），当前转换阈值为0.18米：达到阈值编码100，否则按比例向上取整编码0—99。同格多点取最大代价，不能让地面回波覆盖同格障碍。阈值是暂定几何规则，不是G1经过实测标定的完整能力边界，也不是土壤松软度。
- 地图为map坐标下32×32米、0.1米/格；只更新实际地形输出点覆盖的单元，未观测-1。保留历史观测30个仿真秒，过期恢复未知；新雷达会话清空。不自动填充机器人脚下、盲区或被遮挡区域。
- 雷达下视角扩展到-85°；使用命中网格ID滤掉机器人自身回波，遮挡仍保留。不能将“滤掉自身点”误认为“能透过机器人看到地面”。
- /navigation/mapping_status上报source=cmu_lidar、已知/禁行/未知计数与ready。雷达或地形输出停止更新时，任务监视撤销控制许可；恢复后旧故障任务不会自动续跑。
- 已观测点之间仍可能存在未知间隙，机器人自身也会造成近地盲区。当前不提供自动探索、盲区清空或未知区域穿越；目标未知或没有已知可行路径时会拒绝/规划失败。整套就绪不等于任意目标可达。
