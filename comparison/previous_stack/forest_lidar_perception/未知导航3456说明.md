# 未知环境导航第3—6项

2026-11-13。代码已接入当前一键启动入口；本次没有改G1策略、训练脚本、IsaacLab核心或足迹/未知区域安全阈值。

## 当前实际链路

Isaac三维森林 → 机器人身上的模拟LiDAR → CMU地形分析 → 全局/局部二维代价图 → 未知环境目标管理器 → Nav2规划与跟踪 → 原速度适配器 → 原G1 ONNX策略。

管理器复用[ROS 2 explore_lite](https://github.com/robo-friends/m-explore-ros2)的FrontierSearch；上游固定在326cf8a0b487c34246bb8f3326afbcd69576dc60，源码及许可证保留在third_party/m-explore-ros2。本项目直接编译其搜索文件，没有改上游文件，也没有启动上游另一个会抢发目标的探索节点。Smac、DWB和Rotation Shim继续由Nav2提供。

## 第3项：未知终点与中间目标

用户输入最终map坐标和航向。已知禁行、高于暂定停稳代价上限25、地图边界之外的目标仍拒绝；未知目标允许交给管理器。

终点已知且Nav2可规划时直接执行最终目标。否则从已知区选观察位置：离未知边界约0.65—1.4米、离机器人0.8—4米，候选中心代价不超过25，并避开Nav2膨胀图的未知、内切区和致命障碍。候选还必须通过真正的ComputePathToPose检查。管理器只发送已知区的目标，未知格没有变为自由，也没有打开allow_unknown。

到达观察点后短暂等待新观测，重新判断最终目标。当前在每段完成后切换目标，不在行进过程中频繁抢占重规划；每段内部的周期性重规划仍由Nav2行为树执行。

## 第4项：探索选择

上游FrontierSearch负责寻找连通的已知/未知边界。项目层根据接近最终目标、当前行程和边界规模排序，选择彼此分散的观察点。已失败和已经观察过的位置，在本次任务中以0.8米半径排除；新任务重新计算，不把一次失败永久写进地图。

这是有最终目标的探索导航，不是保证覆盖整片森林的自主巡检。2026-11-13第3步已将初始32×32米地图改为按观测扩展、最大256×256米；当前范围外目标接纳规则仍保留。没有可达前沿时只有限等待，不能据此断言整个真实环境不可达。

## 第5项：停止、受阻与故障

- 上层任务、下层子目标分别有UUID；替换目标必须等旧子目标取消确认后再执行。
- 停止按钮既取消原生Nav2目标，也通知上层结束整次任务，防止停止后又自动发下一个观察点。迟到的接受响应会被撤销。
- 状态/地图/TF失效或定位会话变化，停止旧任务；数据恢复后不自动续跑旧任务。
- 上层状态超过1秒未更新时，独立task_guard撤销控制许可；进程退出也会触发整套启动的退出清理。
- 单任务默认240墙钟秒、单段70墙钟秒，最多12段、6次失败。受阻后换候选或等待新观测，预算耗尽返回blocked；没有自动盲退、清空障碍或驶入未知区域。
- 取消5秒未确认时锁定新目标，安全监视撤销许可，需要重启本次导航会话。
- JSON状态保留具体reason_code；Humble的NavigateToPose结果本身没有错误文字字段，因此不能只看Action状态了解详细原因。

## 接口和文件

| 入口/输出 | 类型 | 责任 |
|---|---|---|
| /navigation/navigate_to_goal | nav2_msgs/action/NavigateToPose | 用户最终目标，允许目标当前未知；激光模式面板和CLI已自动使用 |
| /navigate_to_pose | 同上 | 管理器发送的已知区子目标；直接调用会绕过上层探索 |
| /navigation/frontiers | std_srvs/srv/Trigger | explore_lite搜索接口；success和JSON frontiers，包含size与map坐标points；不直接发目标 |
| /navigation/exploration_status | std_msgs/String JSON v1 | 上层phase、目标、子目标、UUID、reason_code、会话等 |
| /navigation/mission_status | std_msgs/String JSON v1 | 面板统一状态，合并上层任务与独立安全监视结果 |
| /navigation/cancel | std_srvs/srv/Trigger | 取消整次任务；提交成功不等于实际制动完成 |
| /navigation/stop_requested | std_msgs/Bool | task_guard内部停止通知，true使上层当前任务失效 |

实现：nav2_path_tracking/forest_nav_control/unknown_navigation.py负责ROS任务生命周期；exploration_policy.py负责候选选择；forest_lidar_perception/frontier_bridge负责调用上游搜索。launch/tracking.launch.py只在lidar模式启动它们，offline模式继续使用原生目标入口。

每次任务事件保存在forest_lidar_perception/results/missions/<上层UUID>.json；可用FOREST_NAV_MISSION_RESULTS指定其他记录目录。失败原因、观察点、最终结果一起归档。

## 启动

通常直接运行：

```bash
/home/ubuntu/robot_projects/forest_nav/forest_navigation/start_forest_navigation.sh
```

会打开仿真、G1原策略、激光在线地图、Nav2和坐标面板。输入的是map坐标，面板航向为度。自动目标示例（航向为弧度）：

```bash
/home/ubuntu/robot_projects/forest_nav/forest_navigation/start_forest_navigation.sh --goal 6 1.5 0
```

迁移源码到新机器后需先构建两个本地接口：

```bash
bash /home/ubuntu/robot_projects/forest_nav/forest_lidar_perception/build_cmu.sh
bash /home/ubuntu/robot_projects/forest_nav/forest_lidar_perception/build_frontier.sh
```

现有启动预检会在缺少构建结果时给出提示，不会偷偷安装或编译。
