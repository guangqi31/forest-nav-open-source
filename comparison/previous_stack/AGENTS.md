# 项目开发约定

## 用户明确要求：只写适配，不写算法

- 只编写现有开源模块之间必要的消息、坐标、时间、模型输入输出和标准插件接口适配。
- 规划、控制、感知、建图、任务执行、到达判断和恢复等算法优先使用成熟开源实现。
- 不擅自新增自写算法、速度限制、状态许可、否决条件、任务时限、自动退出或恢复逻辑。
- 开源框架不能满足需求时，先说明具体缺口与现成方案，由用户决定；不得自行补算法。
- 不将自写算法改称“适配器”后继续使用。必须说明上游算法、自写接口、项目配置各自的边界。
- 修改前备份；注释用中文。验证代码不混入生产运行链。

## 强制持续运行约束（2026-11-18）

- 用户要求：导航运行期间不得因暂时规划失败、无进展、碰撞、摔倒、达到步数或录制结束而自动结束整次导航、重置机器人或关闭仿真。
- 使用开源BT原生节点承接子任务失败，保持目标执行。无有效规划或控制输出时允许零速度等待，不能重放旧路径、旧速度或伪造成功。
- 不增加自写规划/控制/恢复算法。保留用户手动取消、关闭窗口及停止进程的控制权；到达目标后仿真及策略继续运行。
- 不承诺驱动/进程崩溃或初始化失败后还能执行；不靠吞掉底层异常伪装正常运行。
