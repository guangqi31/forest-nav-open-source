# 原生接口与阶段边界

## 当前集成方案

采用固定版本CMU Humble配套组件、FAR humble-jazzy、FAST_LIO_Hesai ROS2。
Go2工程只作参考，不参与默认构建。不加入Nav2，不创建自写规划、控制或状态估计算法。

桥接②使用CMU原生loam_interface，本项目只新增forest_navigation_bringup配置和启动文件。
接口已用独立ROS域临时定位/点云输入检查；尚未用实际FAST-LIO/G1运动联合验收。

## 接口与语义

| 连接 | 消息及坐标 | 处理 |
|---|---|---|
| FAST-LIO定位→loam_interface | /Odometry，Odometry，camera_init/body；位姿对应IMU | 配置输入话题，flipStateEstimation=false |
| FAST-LIO配准点云→loam_interface | /cloud_registered，PointCloud2，camera_init世界系 | flipRegisteredScan=false，不再次变换点坐标 |
| 原生接口→CMU/FAR | /state_estimation，map/sensor；/registered_scan，map | 保留输入时间戳，camera_init与map定义为同一坐标 |
| 地形分析→FAR | /terrain_map_ext→/terrain_cloud | intensity为地形高度量 |
| 局部地形→FAR | /terrain_map→/terrain_local_cloud | 回调按intensity分类，不能用雷达反射强度 |
| 配准扫描→FAR | /registered_scan→/scan_cloud | 提供当前扫描几何 |
| 目标→FAR | /goal_point，PointStamped，map | 使用原生RViz GoalpointTool |
| FAR→localPlanner | /way_point，PointStamped，map | 原生直接连接 |
| localPlanner→pathFollower | /path，Path，vehicle | 原生直接连接，不能当成map路径 |
| pathFollower→G1桥接③ | /cmd_vel，TwistStamped，vehicle | 使用既有速度适配器；本阶段只测试隔离话题 |

FAST-LIO的/path是历史轨迹，sensor_bridge.launch.py已将其重映射为/lio/path，避免进入跟踪器。

## 坐标及时间

TF链：map→camera_init(静态单位变换)→body(FAST-LIO动态)→sensor(静态单位变换)→vehicle(原生sensorOffsetX/Y)。
当前IMU在G1躯干原点并与其同向；导航参考点取该点。雷达0.25m偏移由FAST-LIO外参使用，不能再加到IMU定位上。
map是本地建图坐标，不自动等于Isaac世界坐标；本包不写仿真真值定位对齐。
loam_interface.sendTF=false，避免重复发布动态位姿。所有上层节点use_sim_time=true。

## 与上游启动示例的明确差异

FAR默认is_static_env=true，本项目以false启用在线观测输入。
原生far_planner.launch将scan_cloud接terrain_map、terrain_local_cloud接registered_scan。
本包按FARMaster::ScanCallBack/TerrainLocalCallBack及ExtractFreeAndObsCloud实际语义对调，避免用雷达反射强度当高度。
修改仅在本包launch，不改上游源码。
其余FAR参数来自原生default.yaml；CMU参数由固定版本原生launch原值展开到navigation.yaml。

## 尚未验收

机器人尺寸、速度、地形阈值保留上游基线，尚未完成G1标定。
FAST-LIO当前Odometry没有填充有效twist，不能当实测速度；没有另写估计算法填充。
上游本身的减速、停车、目标调整等算法行为仍存在，不能宣称开源没有限制。
真实传感器→FAST-LIO→上层链路、G1运动闭环、未知环境导航、RViz GUI尚未在本阶段验收。
