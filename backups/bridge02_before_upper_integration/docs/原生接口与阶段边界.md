# 原生接口与阶段边界

## 本次选择

CMU完整开发环境humble + FAR humble-jazzy作为原生导航基线。Go2 foxy-humble整套工程仅作为腿式接口参考，不把两套localPlanner/pathFollower混着启动，不增加Nav2中间转换。

## 原生连接

| 连接 | 消息/话题 | 本次是否编写转换 |
|---|---|---|
| 用户目标→FAR | geometry_msgs/PointStamped，/goal_point，map | 否 |
| FAR→localPlanner | geometry_msgs/PointStamped，/way_point | 否，原生兼容 |
| localPlanner→pathFollower | nav_msgs/Path，/path，vehicle帧 | 否，不能当作map帧折线重解释 |
| pathFollower→机器人端 | geometry_msgs/TwistStamped，/cmd_vel，vehicle帧 | 尚未编写，后续仅适配G1策略输入 |
| 定位→配套模块 | nav_msgs/Odometry，/state_estimation | 尚未编写，后续核对安装偏移及坐标语义 |
| 配准点云→地形分析 | sensor_msgs/PointCloud2，/registered_scan | 尚未编写 |
| 地形分析→局部/全局规划 | /terrain_map、/terrain_map_ext；XYZI中intensity带地形量 | 无自写2D代价地图转换 |

FAR官方launch原有重映射：/odom_world→/state_estimation、/terrain_cloud→/terrain_map_ext、/scan_cloud→/terrain_map、/terrain_local_cloud→/registered_scan。此处只记录，未新增launch。

## 后续必须核对的开源行为

- localPlanner与pathFollower原生就有尺寸、速度、加速度、转向、减速、停车等参数，不能承诺开源没有限制，也不擅自添加第二层。
- 自主/手柄模式必须按原生配置说明启动，不能误把等待手柄当作规划失效。
- Go2工程含Unitree Sport接口和is_real_robot选项。Isaac/G1阶段不能启动Go2真机控制输出；只使用明确的仿真速度接口。
- Go2验证不代表G1验证；持续位置保持、最终朝向、停车精度及G1稳定性尚未核对。
- 官方模型不随仓库完整提供，需要第2阶段通过上游下载方式准备。
